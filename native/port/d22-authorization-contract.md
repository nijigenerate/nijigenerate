# D22 authorization and approval state contract

Status: source contract submitted for independent review; no runtime proof.
Sources: current `api/mcp/auth.d`, `api/mcp/http_transport.d`, and
`widgets/notification.d` under `source/nijigenerate`. D21 is the accepted
transport prerequisite. This document preserves current behavior rather than
inferring behavior from OAuth terminology or source comments.

## Approval lifetime

`ngSimpleAuth` starts with an empty decision and popup ID zero. It first waits
for a queued main-thread action to install a callback popup with duration120.
Only after installation completes does it calculate the wall-clock deadline
as `Clock.currTime() + approvalTimeout`, whose initial value is120 seconds.
It checks the clock before checking the decision, then cooperatively sleeps
200ms if no decision exists. The popup's independent remaining-duration clock
is driven by ImGui DeltaTime; expiry or clearAll does not assign a decision.

Deny assigns `deny` and closes that ID. Approve assigns `approve` and closes
that ID. These are sequential independent if statements, not else-if, so the
original callback's control order must be retained. `close` marks matching
items closed; the update pass removes closed/expired items. Closing does not
cancel the caller's waiting operation or synthesize a denial string.

After the polling loop, another queued main-thread action closes the same ID,
then the function returns the current decision. It does not recheck popup
openness or replace an empty decision itself. There is no scope-exit cleanup
around interrupted sleep or failed dispatch; preserve failure order and
retained callback/request lifetimes. Synchronizing cross-thread decision
publication is a native memory-model responsibility, not evidence that the
unsynchronized original races have a deterministic total order.

## Authorization endpoint transitions

The handler defaults client to `mcp-local`, scope to `mcp:use`, method to S256,
and the other absent query fields to empty strings. It rejects unless response
type is `code`, redirect URI is nonempty, canonicalResource starts with the
supplied resource, and challenge method equals S256. These are the actual
predicates: there is no separate nonempty resource/challenge check here.

Redirect validation is a literal prefix check for `http://127.0.0.1`,
`http://localhost`, or `https://`. It is not parsed-host equality. Failure
returns400 with `invalid_request` or `invalid_redirect_uri` respectively,
without creating an approval request. The accepted path creates a request ID,
calls ngSimpleAuth with all original request fields, and maps an empty decision
to deny. Only exact `approve` issues a code; every other decision denies.

Approval stores client, redirect, challenge, scope, resource, and current time
plus365 days under the generated code before writing a302 response. Location
is direct concatenation with `?code=...&state=...`; denial concatenates
`?error=access_denied&state=...`. No URI re-encoding/query merging is present.
Exceptions propagate without a local rollback/cancellation handler.

## Token and resource state

All three databases are transport-instance fields, initially empty. Tokens are
prefix plus unpadded base64url of32 bytes generated by the original uniform
byte draws. Exact random strings are not suitable deterministic comparison
outputs; the actual RNG/provider mapping remains a separate implementation
obligation. Do not silently change collision/overwrite behavior in this port.

The form parser splits on ampersands and each pair on equals, uses only the
first value segment, decodes each component, and assigns into the associative
array. Later duplicate decoded keys overwrite earlier values. Decoder/range
exceptions are not caught locally. Preserve actual parsing behavior rather
than assuming a different HTTP library's default form decoder is equivalent.

For authorization_code, a missing code returns400 invalid_grant. An existing
code is copied and removed immediately, before all subsequent checks. Expiry
uses `now > expiresAt`; exact equality is not rejected by that comparison.
Wrong redirect/client or mismatched SHA256/base64url verifier returns
invalid_grant; unequal resource returns invalid_target. Every such failure
after lookup has already consumed the code. Success stores a new access token
with subject `local-user`, expiration now+3600 seconds and a new refresh-token
mapping, then returns200 JSON including both tokens, Bearer type,3600,scope.

For refresh_token, require both the refresh mapping and its access-token entry;
missing either returns invalid_grant. Require exact resource equality or return
invalid_target. The original does not test old access expiry or client identity
in this branch. Success creates a new access entry, updates the same refresh
token to point at it, and retains the old access entry. No rotation/removal of
the refresh token occurs. Unsupported grant types return400 unsupported_grant_type.

Protected request validation accepts an existing access entry only when
`now < expiresAt` and the requested resource starts with its stored resource.
This expiry comparison differs from code exchange. It does not prune expired
entries. HTTP handlers require the exact `Bearer ` prefix when authEnabled;
otherwise their token gate is bypassed. Failure returns401 with the actual
resource-metadata challenge and invalid_token JSON. Token maps are not persisted
by these source paths, and no explicit revocation endpoint is defined here.

The actual protected routes are POST /mcp and GET /events. Discovery,
authorization and token routes are registered without that gate. Authorization
and token handlers do not themselves test authEnabled. An SSE connection is
checked once at entry; its heartbeat loop tests running and stream failures,
not token expiry or a later authEnabled change. Shutdown closes retained streams
but does not explicitly clear the three token/code databases. Transport object
destruction and explicit revocation must not be conflated.

The form's decoder is the actual `std.uri.decodeComponent`, whose installed
implementation invokes URI_Decode with reserved-set zero and emits UTF-8.
Preserve this URI-component decoder boundary rather than substitute a browser
form decoder. Invalid encoding behavior must be observed against that actual
callee during grouped implementation verification. The constructor initializes
authEnabled true and builds the issuer/canonical resource from the supplied
host/port; changing the bool does not reset token state.

## Native boundary and required grouped evidence

Use the actual request/query/body decoder, JSON, retained strings/maps,
clock/duration, hash/base64/RNG, popup identity and cooperative task providers.
Keep the same transport-instance database ownership and main-thread popup
operations. Multiple pending approvals must not share decision or popup IDs.
The portable implementation must not add direct OS authentication or socket
APIs to this logic; unavoidable platform behavior belongs to D21 adapters.

Verification must compare valid approval/denial/timeout and popup expiry;
interruption before/after installation and final close; concurrent retained
requests; exact prefix and empty-input boundaries; malformed/duplicate forms;
code consumption on every failure; equality at each expiry boundary; PKCE
bytes; refresh reassignment and retained old-token validity; response status,
headers/body and mutation order. Use the actual D functions and native providers,
with controlled clock/random inputs at their real boundaries where supported.
No live listener, credentials, policy change or runtime verification occurred
while drafting this contract. Independent review and these evidence gates remain.
